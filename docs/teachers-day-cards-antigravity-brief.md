# Teacher's Day Cards — System Design + Antigravity Build Prompt
(mulearn ASI club project)

---

## PART 1 — SYSTEM DESIGN (SDN)

### 1. Overview
A web app where users sign in with Google, create a personalized "Teacher's Day card" from a template (photo + teacher's name + message), publish it as a shareable link, and let anyone view it (flip animation reveals the message). Public profile pages list a user's cards. A leaderboard ranks users by cards created.

### 2. Core entities

**users**
- id (uuid, pk, = Supabase auth user id)
- email
- display_name
- avatar_url
- username (unique, slug, for profile URLs)
- created_at

**templates**
- id (uuid, pk)
- name
- category (Bold / Soft / Floral / Minimal / Vintage / Playful / Retro)
- preview_image_url (Cloudinary)
- background_config (json — colors, decorative asset positions, text style defaults)
- is_active (bool)

**cards**
- id (uuid, pk)
- owner_id (fk -> users.id)
- template_id (fk -> templates.id)
- teacher_name (text)
- message (text)
- photo_url (Cloudinary secure_url)
- photo_public_id (Cloudinary id, for transformations/deletion)
- share_slug (unique, short random string — used in share URL)
- like_count (int, default 0) — optional, seen in leaderboard mockups
- created_at
- updated_at

**card_views** (optional, lightweight analytics)
- id
- card_id (fk)
- viewed_at

### 3. Auth
- Supabase Auth, Google OAuth provider only. One "Continue with Google" button.
- On first login, a `users` row is upserted (trigger or app-side) from the Supabase auth session (email, name, avatar from Google profile).
- RLS: users can only insert/update/delete their own rows in `cards`; anyone (including anon) can `select` published cards by `share_slug` or by `owner_id` for public profile viewing.

### 4. Storage / media
- Cloudinary holds all uploaded teacher photos and template preview assets.
- Client uploads directly to Cloudinary via a signed upload (signature generated by a small Supabase Edge Function so the API secret never touches the client) — keeps it serverless, no custom backend needed.
- Store only the returned `secure_url` + `public_id` in `cards`.

### 5. Key flows
1. **Login** → Google OAuth via Supabase → user row upserted → redirect to dashboard ("Create" / "My Cards" / "Leaderboard" / "Profile").
2. **Create card** (5 steps, matches mockups):
   Pick Card (template gallery, filter chips) → Add Photo (upload or camera capture, goes to Cloudinary) → Create (choose text style/font/color, edit message + teacher name, drag/resize on canvas) → Preview (front/inside, zoom/rotate) → Share (get link, "Share Digitally" / "Print/Download").
3. **Publish** → insert row into `cards`, generate `share_slug`, return shareable URL `/{share_slug}`.
4. **View card** (public, no login required) → fetch by slug → shows card front closed; on click/tap it flips (CSS 3D transform) to reveal photo + message.
5. **Profile page** (`/u/{username}`) → public, lists all cards that user has published, in a grid.
6. **Leaderboard** (`/leaderboard`, tabs: This Week / This Month / All Time) → ranks users by `count(cards)` (or by total likes if you want engagement-based ranking) in that window; highlights the current user's own rank even if outside top 5 (per mockup's "Your Rank" pinned row).

### 6. Suggested routes
```
/                      landing (mockup: "Make a Teacher's Day Card")
/login                 Google sign-in
/create                step 1: pick card
/create/photo          step 2: add photo
/create/edit           step 3: create/edit text
/create/preview        step 4: preview
/create/share           step 5: share
/c/{share_slug}         public card view (flip)
/u/{username}           public profile — all cards by user
/leaderboard            leaderboard (This Week / This Month / All Time)
/my-cards               logged-in user's own cards dashboard
```

### 7. Tech stack
- Frontend: Next.js (React) or plain Vite+React — Antigravity can choose based on scaffold speed; Tailwind for styling to match the warm cream/red "scrapbook" aesthetic in the mockups (torn paper, washi tape, hand-drawn doodles, Polaroid frame).
- Backend/DB/Auth: Supabase (Postgres + Auth + Row Level Security + 1 Edge Function for signed Cloudinary uploads).
- Media: Cloudinary (unsigned preset is NOT recommended; use signed upload via edge function).
- Hosting: Vercel/Netlify (static+serverless friendly).

### 8. Non-functional notes
- Mobile-first: mockups show near-identical desktop/mobile layouts with a bottom tab bar on mobile (Create / Templates / My Cards / Leaderboard / Profile).
- Card canvas should be built so template configs are data-driven (json), not one hardcoded component per template — new templates should be addable without new code.
- Keep the flip-card interaction as a reusable component (`<FlippableCard>`), since it's used both in the public share view and potentially in profile/leaderboard thumbnails.
